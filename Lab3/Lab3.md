# Классы

## 1.1. Account (Абстрактный)
**Описание:** Базовый класс для всех пользователей системы.

**Поля:**
- `login`, `password` – данные для входа
- `role` – тип учетной записи (`USER`, `ADMIN`, `GOVERNMENT_SERVANT`)

**Методы:**
- Стандартные геттеры/сеттеры (на диаграмме не указаны)

**Связи:**
- Родитель для `User`, `Admin`, `GovernmentServant` (наследование)
- Использует `AccountRole` (зависимость)

---

## 1.2. User
**Описание:** Пользователь, подающий заявки.

**Поля (дополнительно к Account):**
- **Личные данные:**
  - `name` - ФИО в строковом формате
  - `birthDate` - дата рождения
  - `purpose` - цель визита
  - `phoneNumber` - номер телефона
  - `citizenship` - гражданство
  - `passport` - серия и номер паспорта в строковом формате
  - `email` - адрес эл. почты
  - `inn` - номер ИНН

**Связи:**
- Ассоциация с `Application` (у пользователя может быть много заявок)

---

## 1.3. GovernmentServant
**Описание:** Госслужащий, обрабатывающий заявки.

**Поля (дополнительно к Account):**
- `department` – отдел, в котором работает

**Связи:**
- Ассоциация с `Application` - госслужащий связан с заявками, которые он обрабатывает, но не владеет ими.
---

## 1.4. Admin
**Описание:** Администратор, управляющий услугами и правилами.

**Связи:**
- Ассоциация с `Service` - администратор создаёт и редактирует услуги, администратор добавляет и изменяет правила для услуг.

---

## 1.5. Application
**Описание:** Заявка на услугу.

**Поля:**
- `applicationId` - уникальный идентификатор
- `status` – текущий статус (`PENDING`, `APPROVED`, `REJECTED`, `IN_PROGRESS`)
- `comment` – комментарий госслужащего
- `subDate`, `execDate` – даты подачи и исполнения
- `user` – указывает, какой пользователь подал заявку
- `service` – определяет, на какую услугу подана заявка

**Связи:**
- Ассоциация с `Service` (заявка не существует без услуги)
- Ассоциация с `User` (заявка принадлежит пользователю)
- Ассоциация с `GovernmentServant` (Заявка знает, какой госслужащий её обрабатывает)
- Использует `ApplicationStatus` (зависимость)

---

## 1.6. Service
**Описание:** Услуга, на которую подается заявка.

**Поля:**
- `serviceId`- уникальный идентификатор
- `name`, `description` – название и описание услуги
- `period` - период действия услуги в днях
- `rules` – список правил для получения услуги

**Связи:**
- Ассоциация с `Rule` - Правило не имеет смысла без услуги

---

## 1.7. Rule
**Описание:** Правило для получения услуги.

**Поля:**
- `ruleId` - уникальный идентификатор
- `description` - описание правила
- `parameter`, `checkParameter` – условия проверки
- `compOperator` – оператор сравнения

---

# 2. Классы полного цикла

## 2.1. Репозитории
### **UserRepository**

**Методы:**
- `save()`, `findById()`, `findByLogin()`, `findAll()`, `delete()`, `findByRole()`.

**Связь:** Зависимость c `User` - репозиторий содержит коллекцию пользователей и обеспечивает доступ к ним.

### **ApplicationRepository**

**Методы:**
- `save()`, `findById()`, `findByUser()`, `findByStatus()`, `updateStatus()`.

**Связь:**
Зависимость c `Application` - репозиторий хранит и управляет заявками, но не является их владельцем.

Зависимость с `User` - предоставляет методы для взаимодействия с заявками, связанными с конкретным пользователем.

### **ServiceRepository**
**Методы:**
- `save()`, `findAll()`, `findByName()`, `findById()`.

**Связь:** Зависимость c `Service` - репозиторий содержит коллекцию услуг и обеспечивает доступ к ним.

---

## 2.2. Сервисы

### **UserProfileService**

**Поля:**
- `userRepository` - для взаимодействия с репозиторием

**Методы:**
- `submitApplication()` – создает новую заявку
- `updateProfile()` – редактирует данные
- `getUserApplications()` - возвращает заявки пользователя
- `createServant()` - для создания админом учетной записи для госслужащего
- `createAdmin()` - для создания админом учетной записи для админов
- `createUser()` - для создания админом учетной записи для пользователя

**Связь:** Агрегация с `UserRepository` - сервис тесно связан с репозиторием и использует его для доступа к данным пользователей.

### **AuthService**

**Поля:**
- `userRepository` - для взаимодействия с репозиторием

**Методы:**
- `authenticate()` - для входа в аккаунт
- `getUserRole()` - для получения роли пользователя

**Связь:** Агрегация с `UserRepository` - сервис аутентификации зависит от репозитория пользователей для проверки учётных данных и получения роли пользователя.

### **ApplicationProcessingService**

**Поля:**
- `applicationRepository` - для взаимодействия с репозиторием
- `ruleValidationService`

**Методы:**
- `processApplication()` – выполняет действие по заявке (одобрить/отклонить)
- `setStatus()` - устанавливает статус заявки
- `addComment()` - добавляет комментарий
- `completeApplication()` - для закрытия заявки госслужащим. В аргументах метода присутствует comment, который будет отображать результат заявки, например, 'Паспорт готов к выдаче'
- `getApplicationsByStatus()` - для получения заявок по статусу
- `getApplicationById()` - для получения заявки по id

**Связь:** Агрегация с `ApplicationRepository` - сервис обработки заявок зависит от репозитория заявок для выполнения операций с заявками (изменение статуса, добавление комментариев).

### **ServiceManagementService**

**Поля:**
- `serviceRepository` - для взаимодействия с репозиторием

**Методы:**
- `createService()` - метод для создания новой услуги в системе.
- `addRuleToService()` - метод для добавления правила к определённой услуге.
- `getServiceById()` - метод для получения услуги по её идентификатору.
- `updateService()` - метод для редактирования услуги
- `deleteRule()` - метод для удаления правила

**Связь:** Агрегация с `ServiceRepository` - сервис управления услугами зависит от репозитория услуг для создания и управления услугами.

### **RuleValidationService**

**Методы:**
- `validateRule()` - метод для проверки правила. Он принимает правило и входные данные для проверки и возвращает логическое значение, указывающее, соответствует ли входное значение условиям правила.
- `validateApplication()` - метод для проверки заявки на соответствие всем необходимым правилам.

**Связь:**  Зависимость от `Rule` - сервис проверки правил использует правила для проверки заявок, но не управляет ими напрямую.

---

## 2.3. Контроллеры (API)
### **UserController**
**Поля:**
- `authService`- используется для проверки учётных данных пользователя и получения его роли.
- `userProfileService` - используется для работы с данными профиля пользователя.
- `applicationService` - используется для подачи новых заявок и управления существующими заявками пользователя.

**Методы:**
- `register()` – регистрация нового пользователя
- `getProfile()` – получение данных пользователя
- `submitApplication()` – подача заявки
- `getUserApplications()` – получение списка заявок пользователя

**Связь:** Агрегация с `AuthService`и `ApplicationProcessingService`, а также с `UserProfileService` - для выполнения операций, связанных с профилем пользователя (обновление данных, подача заявок).

### **GovernmentServantController**
**Поля:**
- `applicationService` - используется госслужащим для изменения статуса заявок и добавления комментариев.

**Методы:**
- `setStatus()` – изменение статуса заявки
- `addComment()` – добавление комментария
- `completeApplication()` - для закрытия заявки
- `getApplicationsByStatus()` - список заявок по статусу
- `getApplicationById()` - получение заявки по id

**Связь:** Агрегация с `ApplicationProcessingService` -  контроллер госслужащего зависит от сервиса обработки заявок для выполнения действий над заявками (изменение статуса, добавление комментариев).

### **AdminController**
**Поля:**
- `authService` - используется администратором для проверки своих учётных данных и получения прав доступа.
- `serviceManagementService` - используется администратором для создания новых услуг, добавления правил к услугам и получения информации об услугах.
- `userProfileService` - используется администратором для создания учеток для пользователей, госслужащих и админов

**Методы:**
- `createService()` – создание новой услуги
- `updateService()` – обновление услуги
- `addRuleToService()` – добавить правило к услуге
- `createUser()` - создание пользователя
- `createAdmin()` - создание админа
- `createServant()` - создание госслужащего
- `deleteRule()` - удаление правила
- `getUserRole()` - получение роли пользователя

**Связь:** Агрегация с `ServiceManagementService`, ` AuthService`, `UserProfileService` - для управления услугами(создание, редактирование правил), для аутентификации и проверки прав доступа администратора, а также дя создания всех учёток.

# 3. Перечисления (Enums)
### **AccountRole**
**Роли:**
- `USER`, `ADMIN`, `GOVERNMENT_SERVANT`

### **ApplicationStatus**
**Статусы заявок:**
- `PENDING` - заявка только что создана и ожидает первичного рассмотрения
- `APPROVED` - одобрена
- `REJECTED` - отклонена
- `IN_PROGRESS` - заявка взята в работу, но ещё не завершена
- `COMPLETED` - услуга выполнена(финальный статус)

### **Action**
**Действия над заявкой:**
- `APPROVE` - одобрить
- `REQUEST_CHANGE` - запросить изменения
- `REJECT` - отклонить

**Связи:**
Ассоциация в `AuthService`, `ApplicationProcessingService`, `UserRepository`.

Ассоциация между `AccountRole` и `Account`.

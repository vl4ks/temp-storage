# Описание акторов и их действий в системе

## Пользователь:
Пользователь — это физическое лицо, которое взаимодействует с системой для получения услуг, связанных с миграционными процессами, трудовой деятельностью и другими административными процедурами.

1. **Вход в систему:**
   - Пользователь выполняет вход в систему и вводит свои данные (логин и пароль).

2. **Изменение параметров:**
   - Используя идентификатор для доступа к своей информации, пользователь может редактировать свои личные данные, такие как ИНН, номер паспорта, ФИО и другие параметры.

3. **Подача заявления на получение услуги:**
   - Пользователь может подавать заявления(заявку) на получение услуги из списка доступных услуг.
   - Заявление заполняется в электронной форме, и пользователь указывает необходимые документы согласно правилам.

4. **Просмотр своих услуг и их статуса:**
   - Пользователь может просматривать статус своих текущих заявок (например, "в обработке", "одобрено", "отклонено").
   - Это позволяет пользователю отслеживать прогресс обработки его заявок и своевременно реагировать на изменения.

5. **Отмена заявки на получение услуги:**
   - Пользователь может отменить заявку на получение услуги

---

## Администратор:
Администратор — это сотрудник, который управляет системой, настраивает правила и дорожные карты.

1. **Вход в систему:**
   - Администратор выполняет вход в систему и вводит свои данные(логин и пароль).

2. **Редактирование дорожной карты:**
   - Администратор может редактировать дорожную карту, изменять существующие правила, которые регулируют процессы в системе. Например, он может изменить сроки подачи документов, требования к документам или порядок обработки заявок.
   - Все изменения сохраняются в базе данных, и система автоматически применяет их ко всем пользователям.

3. **Создание дорожной карты:**
   - Администратор может создавать новые дорожные карты, которые представляют собой последовательность шагов, необходимых для получения определенной услуги.

4. **Добавление правил:**
   - Администратор может добавлять новые правила в систему, которые будут регулировать процессы предоставления услуг.

5. **Создание учетной записи для админов, госслужащих и пользователей:**
    - Администратор создает учетные записи для администраторов, госслужащих и пользователей для того, чтобы исключить риск доступа к системе недоброжелателей.
---

## Госслужащий:
Госслужащий — это сотрудник государственного органа, который отвечает за обработку заявок пользователей и принятие решений по заявкам.

1. **Вход в систему:**
   - Госслужащий выполняет вход в систему и вводит свои данные (логин и пароль).

2. **Изменение статуса услуги:**
   - Госслужащий может изменять статус заявки пользователя. Например, он может перевести заявку из статуса "в обработке" в статус "одобрено" или "отклонено".

3. **Добавление результата услуги:**
   - Госслужащий может добавлять текстовый результат обработки заявки. Например, он может указать причину отклонения заявки или добавить комментарии по поводу принятого решения («Заявка одобрена, выдан патент» или «Заявка отклонена, отсутствует необходимый документ»).
   - Это действие помогает пользователю понять, почему его заявка была одобрена или отклонена, и что ему нужно сделать дальше.

4. **Просмотр результата услуги:**
   - Госслужащий может просматривать результат услуг.
---

Каждое действие связано с конкретными задачами, которые выполняют акторы в системе. Пользователь взаимодействует с системой для получения услуг, администратор управляет правилами и дорожными картами, а госслужащий обрабатывает заявки и принимает решения.
